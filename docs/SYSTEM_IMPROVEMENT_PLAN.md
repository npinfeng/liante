## 实施顺序与验收

1. 保存代码与真实 Stage2 基线；实现 SQLite 任务主存、状态机、公共幂等、容量与权限基础。
2. AOI journal 增加流/产品元数据、可配置视角、独立关闭、终态结算、孤儿帧恢复。
3. 强类型人工证据、撤销/替换/过期、复核、产品追溯、历史、导出接口。
4. 完善中文管理界面与有界日志；不生成任何模型结果。
5. 通用部署 profile、备份恢复与只读一致性工具；最小 CI。
6. 从 Flask 实际注册表生成 API.md / OpenAPI，校验双向覆盖、权限和唯一 operationId。
7. 执行无训练、无伪模型的软件测试与故障注入；在 C209 升级、比较真实预测与权重哈希，登记生产就绪状态。

每项实现与验证结果记录到 `docs/SYSTEM_IMPROVEMENT_REPORT.md`。缺失模型作为范围外的真实状态记录，不作为软件测试伪造成功的理由。已有训练执行/伪模型测试在本轮明确跳过，其余软件行为必须通过实际测试。

## 数据规则

SQLite 是任务、预测行与结构化事件的权威来源；JSON 是可修复快照；JSONL 是追加审计副本。AOI journal 是帧 ACK 的权威来源，产品/流元数据必须在 ACK 事务中存在；父任务丢失可从 journal 重建。证据库保存版本化生命周期和审核事件，分级入口重新检查证据与上游结果。

## 升级边界

不删除用户数据、历史代码、模型、环境或缓存；不新建额外公开监听端口。数据库迁移前备份。C209 保持现有监听方式，通用配置另提供示例。终态任务重试创建新任务并保留关系，迟到回调不能改变旧终态。
