## 2 业务流程与数据关系

业务顺序为：产品进入 AOI 检测，获得外观检测结果；读取光电特征文件并生成 EA/Bias 推荐参数；完成调测、光学与电学测量及人工复核；登记合格证据；为已经合格的产品生成 A/B/C/D 等级。

Stage3 的输入对象是已通过前序检查的产品，等级表示合格产品内部的质量差异。调用方直接提交 `qualified=true` 不能替代服务端合格证据。Stage2 的预测结果用于参数推荐，不自动等同于产品光学、电学合格。

| 标识 | 作用 |
| --- | --- |
| `product_id` | 关联产品或明确的批次；同一产品前序结果与证据需匹配 |
| `task_id` | 标识一次流或推理任务，查询状态、结果、日志及取消 |
| `source_id` | 标识 AOI 设备或 Stage2 输入来源，具体含义由接口确定 |
| `request_id` | 关联外部请求；Stage2 文件夹预测用于同身份重试去重 |
| `qualification_id` | 标识服务端保存的合格证据，供 Stage3 引用 |

设备流允许逐帧指定不同产品编号。目前合格证据登记仍要求 AOI 父任务完成，产品结束与设备流结束尚未完全解耦；该限制需要在持续产线业务接入前处理。

## 3 软件架构与代码组织

系统使用 Python、Flask 和 Waitress 提供 HTTP 服务；Pydantic 校验请求；PyTorch 执行 MLP；Optuna 搜索训练参数；pandas、NumPy 和 scikit-learn 处理数据与标准化；SQLite、JSON 和 JSONL 保存任务、结果与日志。界面使用 HTML、CSS 和 JavaScript。


## 4 Stage1 连续 AOI 检测

设备先调用 `POST /api/v1/aoi/streams` 建立流，再向 `/api/v1/aoi/streams/{task_id}/frames` 连续提交图片、帧序号及可选产品编号。序号从 1 递增。服务将图片和接收信息写入可靠帧日志后返回 202，并异步调用模型适配器。

默认最多 4 路流，每路最多 8 帧等待，单帧最大 2 MiB。队列满返回 429 和 `Retry-After`，设备按同一序号重试。相同序号、产品编号和图片校验值的重复提交可取得原接收结果。结束时调用 `close`，服务停止接收并处理已接收帧。

可查询流状态、接收和处理计数、拒收计数、处理速率、最新图片及历史逐帧结果。原图默认保留 30 天，逐帧结果和校验值继续保留。恢复机制采用至少一次处理语义，下游需按流编号和帧序号去重。

Stage1 模型接口要求真实图片输入，输出 `qualified` 和 `defects`；缺陷项包含类型、原图坐标框及置信度。模型未配置时明确返回或记录 `MODEL_NOT_CONFIGURED`，不会生成虚假的合格结果。异常恢复边界、独立产品结束信号和真实设备长期运行仍需专项验收。

## 5 Stage2 文件夹预测与 MES 接入

Stage2 页面自动读取已登记目录，识别 CSV/XLSX，并从文件名或子目录中的 `channel_0`–`channel_7`、`CH0`–`CH7` 推断通道。界面提供来源选择、递归扫描、文件清单、整批预测、逐文件状态、逐行 EA/Bias 分页及日志，不要求手工填写特征值、单文件路径或通道。

四列特征文件读取全部四列；七列及以上文件读取第 4–7 列；XLSX 默认读取第一个工作表。扫描最多 100 个数据文件、10000 个目录条目、8 层子目录，跳过链接、Windows 重解析点、临时文件和非数据文件。通道不明、冲突、空文件或仍在写入的文件会明确提示。默认文件修改后至少等待 2 秒，并在读取前后核对大小和修改时间。

任务处理提交时识别到的全部文件，当前不持续监视目录新增文件。文件缺少模型或预测失败时继续处理其他文件，保留各项结果；任何一项失败使整批任务为 FAILED，结果接口通过 409 的 `data.result` 返回成功和失败项。失败批次不能登记为 Stage3 合格证据。

MES 与 Stage1 共用现有 HTTP 端口，调用链如下。

| 操作 | 接口 |
| --- | --- |
| 登记或修改输入目录 | `POST /api/v1/inference/ea-bias/sources` |
| 查询来源与配置版本 | `GET /api/v1/inference/ea-bias/sources` |
| 扫描并识别文件 | `POST /api/v1/inference/ea-bias/scan` |
| 提交文件夹预测 | `POST /api/v1/inference/ea-bias/folder` |
| 查询 MES 接入日志 | `GET /api/v1/inference/ea-bias/sources/{source_id}/logs` |

MES 提交 C209 服务账号可读取的绝对目录或 UNC 共享目录。允许范围由 `STAGE2_INPUT_DIRS` 和 `STAGE2_ALLOWED_DIRS` 控制。来源配置持久化，重启保留；`revision` 和 `expected_revision` 支持配置冲突检查。MES 使用独立设备身份，仅能访问自己的来源及任务。

预测必须提供 `product_id`、`request_id`。相同身份、请求编号和参数的重试返回原任务；不同参数复用编号返回 409。回执默认保留 30 天，达到容量上限拒收新回执。目录变更、扫描、提交、重复请求及拒收都写入接入日志，日志默认最多 20000 条且保留 30 天。

## 6 Stage2 AutoML 与模型产物

Stage2 为每个通道独立训练多输出 MLP，四项特征输入对应 EA、Bias 两项输出。Optuna 搜索 MLP 隐藏层、宽度、激活函数、优化器、学习率、正则化、批量大小和调度参数。训练使用 Huber Loss、早停和 trial 剪枝，保留最佳验证指标对应的原始 trial 权重，再进行独立测试评估。

训练 CSV 的特征使用第 4–7 列，目标使用第 12–13 列。数据按原始行序划分为约 70% 训练、15% 验证、15% 测试；Scaler 只在训练集拟合，测试集不参与超参数选择。评价产物记录 MSE、RMSE、MAE、R² 等指标。

训练入口为 `/gui/train.html`、`POST /automl/train`、`POST /automl/train-all` 和 `automl_train.py`。Web 训练默认使用 CPU，默认一个工作任务、两个等待任务。管理员可以提交训练，操作员不能提交训练。

通道模型产物包括 `model.pth`、`config.json`、`scaler_x.joblib`、`scaler_y.joblib`、`metrics.json`、`training_metadata.json`。预测按配置重建 DynamicMLP，加载权重和两个 Scaler。当前实现还涉及版本目录及 `CURRENT` 切换；训练成功后使对应模型缓存失效。单个预测任务固定模型版本、完整发布回滚及训练任务持久化仍需完善。

现有真实文件验证说明模型能够加载并执行预测。模型精度、泛化能力、生产数据分布和调测效果还需按独立验收数据与业务阈值评估，不能由预测条数或接口测试通过直接推定。

## 7 Stage3 合格产品内部质量分级

管理员通过页面或 `POST /api/v1/qualifications` 关联同一产品的 AOI 与 Stage2 任务，录入光学、电学数值测量、调测完成状态，以及复核人、带时区的测量时间和说明。登记时校验任务状态、产品关系、前序完成时间、实际预测记录及配方一致性，默认有效时间窗口为七天。

分级请求使用 `product_id` 和 `qualification_id`，服务从证据存储取得输入。真实适配器需输出 A/B/C/D 等级、0–1 的分数和置信度、原因及规则版本。置信度低于默认 0.8 时进入 `REVIEW_REQUIRED`，自动发布等级为空，保留建议等级。

当前人工录入声明不是仪器自动采集的可信检测记录；测量字段、单位、配方阈值与登录人员身份绑定尚需明确。分级入口对既有证据的有效期再次校验、证据撤销与替代、人工批准或驳回的闭环也需补齐。当前 Stage3 没有配置真实模型，不能产生已验收的真实等级。

## 8 容量控制与故障处理

系统已在主要输入和执行环节设置容量上限。目的在于限制内存、计算和存储压力，并把过载反馈给发送方。队列容量与缓存容量不同；设置有界队列后仍需根据设备速率和长期写入量管理整个链路。

| 环节 | 当前默认限制 |
| --- | --- |
| HTTP 服务 | Waitress 8 个线程，100 个连接上限，backlog 64 |
| AOI 流 | 4 路流，每流 8 帧等待，2 MiB/帧 |
| Stage2 推理 | 1 个工作任务，4 个等待任务 |
| Stage3 推理 | 1 个工作任务，4 个等待任务 |
| Web 训练 | 1 个工作任务，2 个等待任务 |
| 共享模型资源 | 1 个资源槽，默认等待 30 秒 |
| 异步推理时限 | 排队 120 秒，执行 600 秒 |
| Stage2 数据预算 | 32 MiB/文件，100000 条预测/任务，16 MiB 结果/任务 |
| Stage2 分块与分页 | 默认每块 1024 行，API 每页最多 1000 行 |

过载返回 429 和 `Retry-After`，排空期间拒收新任务并返回 503。接口错误码区分目录、数据、模型、容量和执行失败。发送方需要限速、退避重试和自身缓存上限；持续输入高于处理能力时，应联动设备停机或告警策略。

任务支持取消及看门狗超时，普通未完成推理任务在服务重启后标为失败。AOI 从可靠帧日志恢复。当前模型在 Python 线程内执行，任务超时不能强制终止卡死模型调用；资源真实释放需要模型工作进程隔离。终态写入竞态和异常恢复边界也需进一步测试。

## 12 待完善事项与建议顺序

2026年9月30日工程审查记录的部分问题仍适用于当前代码。Stage2 文件夹接口已补充同身份去重、提交前容量预约、来源权限和日志，不能把这些改进扩大为所有接口和故障边界已经修复。

优先处理三个产线接入阻断问题：通用任务入口统一校验编号与目录边界；为持续设备流增加独立产品结束和必需视角检查；按已确认的待处理帧恢复异常父任务，保证已接收数据都有可追溯终态。MES 新任务入口已有编号和归属校验，其他入口仍需统一覆盖。

随后完善证据有效期、撤销和人工复核；模型工作进程隔离；状态转换与终态原子更新；任务多种存储的一致性；不可变模型版本和输入校验；训练状态持久化；磁盘配额、备份及恢复。旧批量预测和 Stage3 等接口仍需分别补充完整的重复请求保护。

生产运行还需明确开发与生产模式，生产缺少凭据时禁止启动；将最高权限计划任务迁移到适当的专用服务账号；固定依赖组合、代码发布版本和 CI；补齐设备客户端鉴权、断线恢复及本地缓存上限。界面需进一步完善历史任务检索、人工复核、结果导出、日志缓存上限和静态依赖管理。

建议按以下顺序继续推进。

1. 修复路径权限、产品生命周期和异常恢复等阻断问题，并增加对应故障测试。
2. 固定测量字段、单位、配方阈值和人员身份，补齐证据与分级复核闭环。
3. 接入经过业务验证的 Stage1、Stage3 模型，记录明确模型与规则版本。
4. 完成真实设备和 MES 联调，确认来源、网络、凭据、重试及发送方容量策略。
5. 依据实际设备数量、帧率、允许延迟和数据保留时间开展持续运行与故障恢复验收，再决定发布。

整体交付验收应至少包括：三阶段真实业务完成；产品与结果关系正确；输入超速时容量受控且拒收明确；已确认数据不丢失；越权和越界读取被拒绝；重试不产生重复业务；超时后实际资源可恢复；备份能够还原；真实模型效果达到项目定义的指标。
